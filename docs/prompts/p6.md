# P6 — Audit Activity Redesign

**Kompleksitas:** COMPLEX — audit domain, search, human-readable UI  
**Dependency:** P2 audit events tersedia; P4 status cleanup dan P5 select selesai  
**Tujuan:** Eksekusi hanya fase P6 terhadap [Zona.ai](http://Zona.ai), bukan membuat rencana tanpa implementasi.

## Tujuan

Log Audit bukan dummy: mutation model/admin user/credit/feedback benar-benar menulis `audit_logs` di backend. Masalahnya administrator membaca `model.disable`, `user.delete`, raw IDs, `USER/MODEL` badge, filter teknis dan JSON sebagai detail utama. Pertahankan fungsi audit, append-only historical evidence, authorization, pagination dan event code internal. Ubah user-facing copy menjadi **Log Aktivitas** (nav, page title, recent activity), deskripsi “Riwayat perubahan yang dilakukan administrator.” Jangan rename DB table atau route `/admin/audit-log` tanpa kebutuhan; jangan menghapus log.

## Audit baseline dan root cause

Baca `src/routes/admin/audit-log.tsx`, `src/server/core/admin-audit.ts`, `server/functions/admin-audit.ts`, `admin/index.tsx`, `admin-dashboard.ts`, admin nav, semua producer audit (`admin-models`, `admin-users`, `credits`, `feedback`, P2 mutation). Baseline `COMMON_ACTIONS` belum menyertakan `user.delete`; admin search hanya `eq(adminId)`; `metadata` dialog JSON. User delete existing punya `deletedEmail`/`deletedName` di metadata, sebagian event lama hanya raw ID atau metadata null. Jangan mengarang before/after legacy. OWASP: [https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) (who/what/when/target/outcome, access control and secret exclusions).

## 1. Shared action dictionary and presentation layer

Buat satu typed domain mapping yang dipakai filter, tabel, detail, Ringkasan. Event codes tetap stabil untuk storage/query. Discover semua kode nyata di repo/P2; tabel minimum berikut:


| Internal                             | UI aktivitas (natural)      |
| ------------------------------------ | --------------------------- |
| `model.enable`                       | Mengaktifkan model          |
| `model.disable`                      | Menonaktifkan model         |
| `model.create`                       | Menambahkan model           |
| `model.update`                       | Mengubah informasi model    |
| `model.delete`                       | Menghapus model             |
| `model.connection_test` jika dicatat | Memeriksa koneksi model     |
| `user.ban`                           | Memblokir pengguna          |
| `user.unban`                         | Membuka blokir pengguna     |
| `user.delete`                        | Menghapus pengguna          |
| `credit.adjust`                      | Menyesuaikan kredit         |
| `credit.reset`                       | Reset kredit (development)  |
| `feedback.status_update`             | Memperbarui status feedback |


Tambahkan setiap event valid termasuk user.delete yang sebelumnya missing. Unknown/legacy event: label netral `Aktivitas lainnya`, raw code tersedia di informasi teknis, bukan blank atau fabricated action. Filter label manusiawi, value tetap code. Jika unknown historically exists, pastikan tetap dapat ditemukan (semua aktivitas; opsi berdasarkan event bila diperlukan). Jangan memakai `model.disable (Nonaktifkan Model)` sebagai copy utama.

## 2. Audit snapshots dan integritas backend

Gunakan metadata schema typed/validated yang dapat parse legacy dan new event secara backwards compatible. P2 sudah menyimpan snapshots model; lengkapi producer user/credits/feedback yang relevan dengan target displayName (minimal necessary), actor snapshot yang sah, before/after meaningful fields bila tersedia, reason, safe outcome, time. Gunakan data yang benar-benar dibaca dari DB/transaction sebelum & sesudah mutation, bukan menebak. Untuk kredit simpan old/new/delta per transaksi; untuk ban/unban alasan/expiry/status; feedback status previous/new; model status/diff metadata yang aman. Successful event ditulis atomik dengan mutation bila appropriate (feedback baseline audit insert bisa terpisah; periksa dan jadikan atomic). Failed connection event jika ada tidak boleh dicatat sebagai success. Append-only, jangan melakukan rewrite history lama untuk melengkapi nama atau before-state. Jangan simpan prompt/chat text/credential, bearer/session/OAuth token, raw headers atau data pribadi berlebihan. Sanitize untrusted reason/metadata, render as text; no raw HTML/injection. Admin-only list/detail/search dan no sensitive payload in raw technical view. Jangan menambah destructive log deletion.

Resolve label preference: historical target snapshot → legacy stored metadata (deletedName etc.) → valid current lookup marked as current when needed → raw ID fallback with `Nama tidak tersedia`. Actor similarly snapshot/adminName/adminEmail authorized fallback; tidak mengasumsikan akun deleted masih aktif. Lookup batch/join, hindari N+1. Unknown metadata parse should not erase event; render available fields safely and explain missing. Jangan memalsukan `Status sebelumnya: Aktif` kalau tidak ada bukti.

## 3. Search/filter dan paging

Search by administrator name/email/ID serta target name/ID and snapshot when available. Server-side parameter validated, case-insensitive partial match where appropriate, safely parameterized SQL; escape wildcard semantics, real limit, no full data download. Filter “Semua aktivitas” dan action human label; search + filter compose sebelum count and pagination. Use deterministic descending time + unique ID tie-break; stable pagination, reset page to 1 on filters, avoid stale response overriding latest query, clamp if result shrinks, load/error/retry/empty states. Existing audit pagination default 20 may stay; P7 aligns reusable pagination component. No auth bypass via search, preserve protected route. If snapshot search needs typed JSON path or dedicated indexed columns, choose based on actual DB contract and volume; avoid arbitrary full metadata search leaking details.

## 4. UI and detail presentation (ready-made components)

Reuse existing admin shell/table and shadcn Table, Dialog/Sheet, Collapsible/Accordion, Input, shared Select P5, relevant primitives from library selection. Text-first, no colored metadata badges, no padded-code pill for action or target, no repeated icons for every cell. Date locale consistent (WIB if explicitly using Asia/Jakarta; time zone label truthful, not browser-local time falsely labeled WIB). Header `Log Aktivitas`, nav `Log Aktivitas`, search placeholder `Cari administrator atau target...`. Show actor name, target name under readable action; technical IDs secondary/detail. Avoid exposing email as primary if name known; hide raw internal ID on first sight, not deleting its evidence.

Details trigger must be accessible, label `Lihat detail`/icon with accessible name. Raw JSON existing copy action may remain inside collapsed technical section; do not show fake values. Detail for user/credit/feedback adapted by type, not same generic list of irrelevant fields. Recent activity in Ringkasan use same action/target resolver so user doesn't see raw codes there (pagination deferred to P7). Keep `Lihat semua` navigate to audit page.

## Acceptance

- Test action mapping covers actual producers incl user.delete/new model events, filter sends internal codes, unknown events stay readable and discoverable. No test of CSS/visual markup. Snapshot transaction tests prove preserved target after delete/retire, mutation rolled back if audit insert failure where required. Historical metadata null doesn't crash, use documented fallback. Verify PII/secret redaction and admin-only authorization; no fake data introduced.
- Test search by name, email, exact/partial ID, target snapshot/deleted user/model, composition with filter and paginated total; stable order tie, race handling; server data only. Component tests for opening detail, expand technical info, copy safe JSON, error, empty, filter change. Current admin dashboard activity and metrics unchanged except presentation, P7 handles paging. Test actual mutations via isolated harness, not manual inserts to real DB. Document required migration and backward compatibility. No browser QA until P9.

Handoff P7: audit list contract, shared human-readable renderer, pagination baseline, per-event details, test result.
