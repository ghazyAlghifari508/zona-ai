# P7 — Admin Pagination — Model AI & Ringkasan

**Kompleksitas:** MEDIUM — server pagination, shared UI  
**Dependency:** P1–P6 selesai; katalog DB, shared Select dan audit presentation tersedia  
**Tujuan:** Eksekusi hanya fase P7 terhadap [Zona.ai](http://Zona.ai), bukan membuat rencana tanpa implementasi.

## Tujuan

Cegah tabel model dan aktivitas di Ringkasan memanjang tanpa batas. Baseline `admin/models.tsx` me-render [`filteredCatalog.map`](http://filteredCatalog.map) tanpa pagination; Ringkasan `admin-dashboard.ts` sudah `.limit(10)` (jadi bukan unbounded), tetapi tidak dapat menelusuri halaman berikutnya. User meminta pagination di dua halaman ini. Jangan paginate kartu statistik atau grafik; pagination hanya untuk list/data table. Preserve overview aggregated metrics, current chart period/data, dan `Lihat semua` menuju Log Aktivitas. Jangan memecah admin page menjadi beberapa route palsu.

## 1. Server-side Model AI pagination

Gunakan repository P1 dan CRUD P2. Implement/reuse server list contract dan Zod input `{page, pageSize, search, provider[, status jika sudah tersedia]}`. Page one-based (default 1), pageSize default 10, choices 10/20/50; server enforce allowed bounded values, safe integer and sanitized query. Count total post-filter sebelum paging, return items dan pagination metadata (`page`, `pageSize`, `total`, `totalPages` plus range if appropriate). Select all allowed published/pending/inactive management entries, exclude retired dari default list sesuai P2 (bila restore flow tersedia, buat filter/view eksplisit, tidak campur retired ke count active). Auto virtual counted exactly once in admin default list; keep ordering consistent, not artificially pin in every page. Case-insensitive filter includes displayName, canonical ID, exact route, vendor/provider per contract, aliases only if stored metadata. Provider options harus berasal dari katalog global, bukan page saat ini. Stable order via configured sort plus unique tie-breaker; deterministic no duplicates between pages in static snapshot. Drizzle count/limit/offset or compatible query; validate DB-side bounds, avoid N+1. Jangan fetch semua rows ke client dan `slice` sebagai solusi akhir. Otoritas admin pada list, workspace public DTO remains complete and separate.

## 2. Ringkasan: Aktivitas terkini

Ganti fixed 10-only feed dengan independently paginated data source (reuse listAuditLogsCore/summary DTO P6). Default 5 records per page, use total and newest-first stable date+ID ordering. Keep recent summary limited on each page; jangan mengubah total stats atau fetch all audit rows. Ideally summary metric/chart loader tetap independen dari audit page changes sehingga flipping page tidak me-recompute seluruh chart jika tidak perlu. Initial page use loader/dehydration pattern repo; cache/query scoped. Show readable action/target from P6, timestamp, `Lihat semua`. Jangan menyembunyikan action lama hanya karena new event dictionary. No additional cards per record; use compact existing activity list.

## 4. Pagination state invariants

- Search/provider/status change resets page 1; pageSize change resets page 1. Debounce search if consistent with architecture; request keyed by filters/page; prevent out-of-order late response replacing latest list. Stable loading and error handling; if showing previous page during load, don't mislabel it as new page or allow actions on wrong target. Preserve selected filter and query on data refresh; URL search params if appropriate and validated, not mandatory new routing architecture.
- Mutation create/retire/toggle updates correct query and totals. If last row on last page retired, clamp to latest valid page and refetch once (no loop). Do not lose search/filter unless user explicitly clears. Existing row actions exact stable ID, never index. Empty result shows `0 model` / `Tidak ada model yang cocok` with clear filter option if relevant, hides/disables impossible navigation, no `1–0 dari 0` or `Halaman 1 dari 0`. Error shows retry, not fake 0 data. Previous/next disabled at bounds (including zero/single page), no duplicate network spam.
- Summary activity pagination changes only feed, not global metrics/chart. On new log arrival, newest-first consistent with data and totals; document offset pagination limits under concurrent inserts, avoid claiming snapshot stability across mutations. Do not use fake data for apparent page navigation.

## 5. Acceptance and tests

Seed isolated DB with synthetic dataset via approved fixture harness, e.g. 53 models and 13 audit events, exact duplicate-name routes, active/inactive/pending, matching and nonmatching providers. Prove server returns &lt;= pageSize, sequence correct, totals reflect global filters, all rows reachable, no duplicate model ID including Auto, retired default absent, invalid bounds rejected, non-admin denied, test page 1/middle/last/empty, change filter resets page, changing page size, concurrent stale response, deleting last row clamps, adding entry updates counts. Summary fixed 5 and metrics unchanged across navigation; link routes to audit. Do not populate real user DB to simulate 53 rows. Unit/component tests for callbacks/disabled state and integration DB pagination; no visual assertion of CSS. Run typecheck/lint/affected tests. P9 will verify actual screens and responsive layouts.
