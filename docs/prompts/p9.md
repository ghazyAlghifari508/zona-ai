# P9 — Final Browser QA, End-to-End Regression & Release Gate

**Kompleksitas:** COMPLEX — seluruh hasil P1–P8 dalam aplikasi nyata  
**Dependency:** P1–P8 selesai, seluruh gate non-browser pass atau blocker eksplisit harus dituntaskan  
**Tujuan:** Eksekusi hanya fase P9 terhadap [Zona.ai](http://Zona.ai), bukan membuat rencana tanpa implementasi.

## Tujuan akhir

Ini satu-satunya fase Browser QA dalam rangkaian task. Setelah P1–P8, verifikasi [Zona.ai](http://Zona.ai) sebagai pengguna nyata dan administrator, bukan sekadar membaca screenshot atau menilai code compile. Final state wajib memenuhi seluruh keluhan awal: katalog AI dikelola sendiri dengan import 9Router, hapus model tanpa menghilangkan chat lama; model baru diberi bars/credit/Vision berdasarkan bukti; status bersih tanpa badge slop; pagination dua halaman; dropdown chevron tidak mepet; audit log terbaca dan nyata; sidebar vertical ellipsis. P9 juga wajib mendeteksi dan memperbaiki regression yang timbul dari seluruh rangkaian. Jangan menambah fitur yang tidak diminta.

## 4. Regression and test honesty

- Complete focused tests covering new behavior, run `bun x tsc --noEmit`, `bun x biome check ./src`, `bun x vitest run`, build and full `bun x playwright test` (or existing equivalent), all bounded. Report command, scope, exact passed/failed/skipped counts, duration, exit codes and actual failures. Check existing security/auth, payments (sandbox only), RAG, streaming, compare partial failures, artifact ownership, rate limit, history, admin queries. No loosening test assertions or introducing test-only production bypass to get green. Existing skipped tests must be identified with reason; don't count skipped as pass.
- Functional E2E assertions should measure behavior/invariants, not CSS classes/HTML snapshots or stochastic answer wording. AI actual smoke test acceptance is protocol/capability verified and separate from unrelated model prose. Do not change tests to match broken implementation; no DB manipulation, no force clicking hidden/disabled controls to skirt user flow, no fabricated route interception success, no ignoring browser console errors/hydration failures/unhandled rejections/failed requests. Distinguish expected negative responses and unexpected failures. No arbitrary sleeps or repeated reruns until pass without root cause.
- For every bug found, write reproducible steps, expected/actual, evidence, severity and affected journey. Regression introduced P1–P8 or blocking core user goal MUST be fixed in P9 via small targeted commits; rerun focused then relevant full gate. Independent pre-existing bug: document and prioritize, fix if tightly linked/safe; don't silently ignore, don't enlarge unrelated scope or claim release-ready if critical. If environment prevents testing, no fake pass; report blocker and exact required condition. Never alter app DB to make screenshots/test clean; fixture setup via isolated harness only.
- Verify eventual consistency across tabs/client cache with normal refetch/focus and server authoritative availability. Check browser console/network, access control and direct server endpoint negative tests. Check mobile horizontal overflow, text contrast against semantic token combinations, button focus/visibility on touch, popover clipping, dialog focus, pagination controls not cut off. Run available axe/a11y suite and record findings. Screenshots redact real PII and credentials.

## 5. Final report and release gate

Provide actual QA artifacts (screenshots by route/theme/viewport/state, trace/test reports with safe redaction), not mock-ups presented as evidence. Provide matrix per original complaint P1–P8 and associated QA scenarios with PASS/FAIL/BLOCKED, commit SHAs, raw test output location, actual model count and pending counts, 18-model eval report ref, unresolved bugs and blockers, cleanup proof (ports/PIDs). Distinguish 9Router external availability from code failures. List every decision/deviation and explain. No push/deploy automatically.

Final target:

1. Admin imports existing 9Router model by ID, validates it and can manage/retire it without code change; historical chats safe.
2. 21 requested retired models absent from new selection, 14 requested routes imported, four retained, Auto preserved; target 19 catalog entries, both DeepSeek separately. Verified selectable count truthful.
3. Bars/Premium/Balanced/Economy, tariffs and Vision reflect reproducible actual evaluation, not guessed; no hidden model fallback.
4. UI no redundant badges, natural Indonesian copy, full model name readable, design consistent in both themes, meaningful statuses and error states.
5. Model AI 10 default/20/50, Ringkasan 5 activities/page, navigation/search/filter work with real data.
6. Consistent shared dropdown spacing; Log Aktivitas understandable and audit trail intact; history vertical ellipsis and actions preserved.

If any required item not met, report status NOT RELEASE READY with precise remediation; do not write blanket “all done.” Acknowledging unavailable external services is expected, not failure to be honest. Browser QA is a final validation phase, not permission to silently change requirements from P1–P8.

## Aturan frontend: component discovery WAJIB sebelum coding

Ini bukan instruksi untuk AI bawaan [Zona.ai](http://Zona.ai). Ini perintah kepada coding agent yang mengerjakan aplikasi [Zona.ai](http://Zona.ai).

1. Inspect komponen reusable yang sudah terpasang (`src/components/ui`, admin layout, chat primitives), `components.json`, dependency/versi serta semantic tokens `src/styles/app.css`. Cek skill shadcn-component-discovery, frontend/UI design, accessibility, Tailwind v4, TanStack sesuai rules dan ketersediaan harness. Jangan menganggap semua library berikut sudah installed.
2. Explore komponen siap pakai dari registry/dokumentasi berikut, bukan membuat ulang primitive dari nol: [shadcn/ui](https://ui.shadcn.com/), [HeroUI](https://www.heroui.com/), [Magic UI](https://magicui.design/), [React Bits](https://reactbits.dev/), [Thinking Orbs](https://www.thinkingorbs.com/#orbs), [Affect UI](https://www.affectui.com/components), [Tuff UI](https://tuffui.com/), [CUI](https://yappologistic.github.io/CUI/), [Sakani UI](https://www.sakaniui.com/). Boleh mengeksplor sumber lain yang kompatibel. Cek kandidat yang relevan, bukan memaksa animasi/komponen dari semua situs masuk produk. Jika situs/komponen tidak dapat diakses, catat; jangan mengarang nama atau availability.
3. Buat discovery log singkat sebelum implementasi: kebutuhan → kandidat + URL source/docs → alasan dipilih/ditolak → kompatibilitas React/Tailwind/Radix/Base UI, lisensi, keyboard/accessibility, light/dark, dependency → komponen yang betul-betul dipakai (lokasi import dan file). WAJIB menggunakan komponen siap pakai yang cocok atau reuse komponen existing yang berasal dari library tersebut; bukan sekadar memberikan link/referensi lalu membangun ulang. Jika belum ada yang cocok setelah riset, custom hanya untuk komposisi domain/primitive yang benar-benar tidak tersedia dan jelaskan bukti. Jangan menambah library besar/parallel design system apabila komponen shadcn/Radix existing cukup. Jangan jalankan installer remote tanpa memahami source/diff/dependency changes; jangan menimpa komponen existing secara membabi buta.
4. Adapt komponen pada Tema [Zona.ai](http://Zona.ai): Notion-inspired UI yang restrained, `paper`, `pure-white`, `ink`, `stone`, `hairline`, `accent` sesuai semantic tokens CSS. Light/dark harus setara. Tidak ada gradient dekoratif, glow, glassmorphism, rounded pill berlebihan, emoji chrome, kartu nested/empty filler, markup demo, placeholder copy, badges untuk metadata rutin, animasi sekadar dekorasi, CSS warna literal tersebar. Jangan mendesain ulang halaman dari nol. Utamakan hierarki teks, whitespace, hairline separation, copy singkat natural Indonesia, ikon fungsional. Jangan menggunakan komponen yang dipilih secara mentah jika bertentangan dengan desain.
5. Ilustrasi dalam prompt adalah wireframe semantik, bukan mock data untuk dirender di aplikasi. Gunakan data aktual dan copy yang dijelaskan; jangan hardcode nama/status/angka ilustrasi. Pertahankan loading/error/empty/disabled, focus/keyboard, screen reader, touch, responsive, serta business logic yang sudah ada. Jangan menambah CTA atau elemen dekoratif yang tidak diminta. Jangan testing className, palet, snapshot markup, struktur visual, atau prose AI; test mekanisme/aksesibilitas/kontrak deterministik. Visual review hanya P9.
