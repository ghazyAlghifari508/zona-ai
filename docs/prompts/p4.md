# P4 — Global Badge, Status & Model Selector Cleanup

**Kompleksitas:** COMPLEX — lintas frontend, UI semantics  
**Dependency:** P1–P3 selesai; gunakan DTO dan metadata terverifikasi  
**Tujuan:** Eksekusi hanya fase P4 terhadap [Zona.ai](http://Zona.ai), bukan membuat rencana tanpa implementasi.

## Tujuan dan scope

Hilangkan UI slop berupa kotak/pill dengan background transparan berwarna, border warna dan teks dengan warna identik untuk informasi biasa; hapus badge redundan. User muak akan emerald/kuning/merah pattern yang dipakai pada hampir setiap status, serta `ADMIN`, `USER`, vendor, Premium dan badge teknis lain yang tidak menolong pemahaman. Bukan sekadar mengganti semua warna menjadiabu-abu atau membuat pill netral baru. Tujuan: teks mudah dipahami, hierarki natural, model name tidak terpotong karena metadata. Jangan redesign seluruh aplikasi; pertahankan fungsi, state, evidence, dan Notion-inspired theme. Audit admin seluruhnya dan surface user yang memiliki badge/status (chat/model selector/compare, settings, feedback, pricing/payment, artifact, nav). Jangan menghapus badge penting numerik, error/security state, actionable controls, atau role enforcement.

## 1. Reproduksi dari kode

Pada baseline `admin/models.tsx`: `bg-success/10 border-success/20 text-success`, nonaktif `bg-danger-soft border-coral/20 text-coral`, provider uppercase dalam box, toggle hijau. `admin/users.tsx` status dan role colored. `admin/feedback.tsx` status dan type badge dengan background/border/text. `admin/index.tsx`/`AdminActivityChart` ringkasan badges, `admin/audit-log.tsx` action/target boxed (P6 mengganti copy dan detail). `ModelSelector.tsx` vendor pill, Premium pill, warning badge, name truncate, selected trigger. Trace `ModelColumn`, `CompareGrid`, footer status, `settings`, `GlobalNav`, feedback, pricing dan semua JSX/copy/status dengan search patterns; buat inventory before→after beserta alasan untuk yang dipertahankan. Jangan menyisir semua rounded styles lalu hapus tanpa memahami fungsi (button/tab/filter chip bukan status badge).

## 2. Semantic presentation standard

Pakai plain text tanpa background/border untuk metadata. Status penting boleh memiliki icon kecil atau warna teks seperlunya; jangan mengganti semua badge dengan status dot dekoratif (termasuk hijau/kuning/merah dot). Warna tidak boleh menjadi satu-satunya pembeda. Red khusus destructive/urgent/failure yang memang memerlukan perhatian, blue accent untuk action/selected. Nonaktif biasa neutral, bukan merah alarm. Status copy natural sentence case.


| Field           | Target presentation                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------- |
| Provider        | OpenAI, Google, Anthropic, xAI dll seperti metadata valid, teks biasa; tanpa uppercase pill     |
| Peran           | Admin / Pengguna, plain text                                                                    |
| Model tersedia  | Aktif, teks netral (check optional apabila membantu)                                            |
| Model nonaktif  | Nonaktif + alasan di subline dengan wrapping/accessible full text                               |
| Model pending   | Belum dievaluasi / Koneksi belum terverifikasi sesuai state nyata, bukan label default palsu    |
| User ban status | Tidak diblokir / Diblokir (bukan sedang online); pilih copy eksplisit sesuai data               |
| Feedback status | Baru / Diproses / Selesai / Ditolak; kategori Umum / Saran fitur / Laporan bug tanpa badge      |
| Kredit          | Angka aktual + unit yang jelas; premium label diganti informasi biaya pada selector             |
| Vision          | Ikon gambar kecil + `Vision` hanya supported terverifikasi                                      |
| Audit           | P6 human-readable; pada P4 hilangkan container redundan, jangan perubahan semantic mapping dulu |
| Count badge     | Boleh jika numerik yang memang memberi salience, bukan dekorasi; hindari redundansi             |


Wireframe sebelum/sesudah (kotak literal menggambarkan visual lama):

```
LAMA                            BARU
[ Aktif ] hijau transparan       Aktif
[ Nonaktif ] merah transparan   Nonaktif
                                Mengalami gangguan
[ ADMIN ] [ USER ]              Admin     Pengguna
[ OPENAI ]                      OpenAI
[ Baru ] kuning                 Baru
[ BUG ] merah                   Laporan bug
```

Switch admin aktif gunakan semantic primary blue atau neutral track untuk off; jelas lewat thumb/state/label. Jangan mengubah aksi disable reason, dialog, ban/unban, feedback state, status payment/retry atau error. Jangan hilangkan visibility error penting demi tampilan bersih. Destructive button bisa tetap red, hindari outline+red tinted background+red text untuk action biasa kalau plain ghost/menu action sudah cukup.

## 3. Model Selector: layout berorientasi nama dan biaya

Keluhan utama: nama seperti Claude Opus dan Muse Spark terpotong karena provider badge, Premium, Sedang tidak tersedia. Heading grup vendor sudah memberi konteks sehingga tidak perlu badge provider di tiap row. Remove redundant vendor chip/premium pill; tampilkan credit/request aktual agar pengguna memahami dampak pemilihan. Pertahankan intelligence bars 2/3/4 dengan evidence verified P3, bukan warna sebagai satu-satunya makna; accessible text/tooltip tier dan score jika relevan. Jangan beri rating Auto atau model pending. Preserve existing intelligence colors bila berguna untuk bar yang fungsional, hindari colored container di sekitarnya. Vision label hanya `supported`, jangan menampilkan icon untuk unknown/unverified. Model disabled tetap terlihat dengan `Tidak tersedia` dan alasan bila ada; retired hilang dari selector (historical label tetap). Pending admin-only sesuai P1–P3; jika surface memang harus menyebut pending gunakan status jujur, tidak dapat dipilih. No UI-generated false status.

Gunakan existing Popover/Command/ListBox/selection components (discovery wajib). Keep model search, vendor grouping, order berdasarkan policy existing, available/disabled/credits, normal/compare modes, checkmark selected, keyboard, model picker responsiveness/mobile. Nama punya prioritas row; metadata pindah ke secondary line, jangan dipaksa dalam satu Flex row. Long names dapat wrap 2 line atau truncation only when truly constrained dengan full accessible name; tooltip saja tidak cukup untuk touch, tampilkan label yang dapat dipahami. Opsi dua DeepSeek terpisah: secondary route label `cor-prod` dan `zro-prod` (atau exact route accessible detail) agar pengguna tahu pilihan berbeda. Jangan menggabungkan route. Gunakan exact ID sebagai key dan comparison selection identity. Avoid third metadata line yang tidak diperlukan; route label boleh di subline tambahan untuk model duplikat. Biaya / selected disabled copy harus konsisten dengan actual registry.

```
Cari model...

       [bars jika verified] · Vision · <tarif> kredit
```

Nama dan kemampuan di ilustrasi bukan klaim capability atau tarif. Render hanya data verified. Auto `Kredit mengikuti model yang dipilih`/range policy derived dan tidak menampilkan 1 kredit hardcoded. Trigger ringkas menampilkan model selection, bukan badge tambahan; jika model unavailable saat katalog berubah, jelaskan error inline/actionable sebelum submit. Preserve copy text, attachment capability, insufficient credits dialog, compare limits, model disabled behavior dan mobile interactions.

## 4. Copy tambahan yang wajib benar

- Admin models title `Model AI`, description `Kelola model yang tersedia di [Zona.ai](http://Zona.ai).`; `Kredit / permintaan`, `Kapasitas konteks`, `Aksi`. Format contextWindow sebagai `Intl.NumberFormat('id-ID')` token count penuh `1.048.576 token`, bukan `1.048,576k tokens`; null `—` dengan accessible/optional explanation, no invented number. Auto context limit adaptif/unknown, bukan universal claim.
- Model cost fixed integer atau adaptive range berdasarkan actual eligible candidates, no misleading `min` only; single source from contract. Format rupiah/credit tetap konsisten, jangan ganti billing.
- Gunakan istilah Indonesia konsisten tanpa copy pemasaran generik, tanpa label dev teknis yang tidak relevan. Jangan menerjemahkan nama resmi brand/model ID. P6 menangani Log Aktivitas copy khusus.
- Perbaiki avatar broken/blank hanya jika ketemu akar masalah yang relevan dan tidak merubah profile photo; jangan fabricate user avatar atau data. Temuan independen dicatat sesuai aturan.

## 5. Implementasi dan tests

Buat primitive kecil shared status text/semantic metadata formatter bila memang mengurangi duplikasi; gunakan ready-made components untuk functional controls. Jangan menginstal library badge untuk mengganti semua badge dengan kotak baru. Explore shadcn/HeroUI primitives, existing slots, relevant registry. Design reference: [https://atlassian.design/components/badge/](https://atlassian.design/components/badge/) ; [https://design-system.service.gov.uk/components/tag/](https://design-system.service.gov.uk/components/tag/) ; [https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) . Rekomendasi visual [Zona.ai](http://Zona.ai) lebih restrained dari contoh sumber; jangan copy visual brand lain secara mentah.

Test deterministic: formatted counts/nulls, exact route options (including two identical basenames), derived credit/tier from contract, capability gate, selected disabled/error state, search/filter/selection/compare rules, accessible labels and focus behavior via component tests, role/status actions unchanged, filter still covers data. No exact className/markup/colors. Check light/dark token usage in code and document expected visual P9. Audit inventory all affected scopes and report any status tags kept with rationale. Typecheck/lint/affected suite/build. Handoff P5: remaining select controls to normalize, component discovery evidence, no new redundant badge patterns.

## Aturan frontend: component discovery WAJIB sebelum coding

Ini bukan instruksi untuk AI bawaan [Zona.ai](http://Zona.ai). Ini perintah kepada coding agent yang mengerjakan aplikasi [Zona.ai](http://Zona.ai).

1. Inspect komponen reusable yang sudah terpasang (`src/components/ui`, admin layout, chat primitives), `components.json`, dependency/versi serta semantic tokens `src/styles/app.css`. Cek skill shadcn-component-discovery, frontend/UI design, accessibility, Tailwind v4, TanStack sesuai rules dan ketersediaan harness. Jangan menganggap semua library berikut sudah installed.
2. Explore komponen siap pakai dari registry/dokumentasi berikut, bukan membuat ulang primitive dari nol: [shadcn/ui](https://ui.shadcn.com/), [HeroUI](https://www.heroui.com/), [Magic UI](https://magicui.design/), [React Bits](https://reactbits.dev/), [Thinking Orbs](https://www.thinkingorbs.com/#orbs), [Affect UI](https://www.affectui.com/components), [Tuff UI](https://tuffui.com/), [CUI](https://yappologistic.github.io/CUI/), [Sakani UI](https://www.sakaniui.com/). Boleh mengeksplor sumber lain yang kompatibel. Cek kandidat yang relevan, bukan memaksa animasi/komponen dari semua situs masuk produk. Jika situs/komponen tidak dapat diakses, catat; jangan mengarang nama atau availability.
3. Buat discovery log singkat sebelum implementasi: kebutuhan → kandidat + URL source/docs → alasan dipilih/ditolak → kompatibilitas React/Tailwind/Radix/Base UI, lisensi, keyboard/accessibility, light/dark, dependency → komponen yang betul-betul dipakai (lokasi import dan file). WAJIB menggunakan komponen siap pakai yang cocok atau reuse komponen existing yang berasal dari library tersebut; bukan sekadar memberikan link/referensi lalu membangun ulang. Jika belum ada yang cocok setelah riset, custom hanya untuk komposisi domain/primitive yang benar-benar tidak tersedia dan jelaskan bukti. Jangan menambah library besar/parallel design system apabila komponen shadcn/Radix existing cukup. Jangan jalankan installer remote tanpa memahami source/diff/dependency changes; jangan menimpa komponen existing secara membabi buta.
4. Adapt komponen pada Tema [Zona.ai](http://Zona.ai): Notion-inspired UI yang restrained, `paper`, `pure-white`, `ink`, `stone`, `hairline`, `accent` sesuai semantic tokens CSS. Light/dark harus setara. Tidak ada gradient dekoratif, glow, glassmorphism, rounded pill berlebihan, emoji chrome, kartu nested/empty filler, markup demo, placeholder copy, badges untuk metadata rutin, animasi sekadar dekorasi, CSS warna literal tersebar. Jangan mendesain ulang halaman dari nol. Utamakan hierarki teks, whitespace, hairline separation, copy singkat natural Indonesia, ikon fungsional. Jangan menggunakan komponen yang dipilih secara mentah jika bertentangan dengan desain.
5. Ilustrasi dalam prompt adalah wireframe semantik, bukan mock data untuk dirender di aplikasi. Gunakan data aktual dan copy yang dijelaskan; jangan hardcode nama/status/angka ilustrasi. Pertahankan loading/error/empty/disabled, focus/keyboard, screen reader, touch, responsive, serta business logic yang sudah ada. Jangan menambah CTA atau elemen dekoratif yang tidak diminta. Jangan testing className, palet, snapshot markup, struktur visual, atau prose AI; test mekanisme/aksesibilitas/kontrak deterministik. Visual review hanya P9.
