# P2 — Admin Model Management & 9Router Import

**Kompleksitas:** COMPLEX — backend, API, admin UI  
**Dependency:** P1 selesai dan terverifikasi  
**Tujuan:** Eksekusi hanya fase P2 terhadap [Zona.ai](http://Zona.ai), bukan membuat rencana tanpa implementasi.

## Objective

Administrator dapat menambah, edit, menguji koneksi, menonaktifkan dan menghapus model AI dari katalog [Zona.ai](http://Zona.ai) tanpa memodifikasi source code setiap kali. Model yang dimasukkan **sudah tersedia atau dapat ditargetkan pada instance 9Router yang dikonfigurasi**. [Zona.ai](http://Zona.ai) tidak membuat provider account, tidak menulis custom model/alias/combo ke 9Router, tidak mengubah credential/gateway settings, dan tidak mencoba bypass limit provider. P3 akan melakukan migrasi 14 ID dan evaluasi menyeluruh; jangan menjalankan migrasi produksi tersebut di fase ini.

## Audit baseline

Baca hasil P1. Pada snapshot sebelum P1, `routes/admin/models.tsx` hanya menampilkan toggle, hardcoded registry, confirmation reason untuk disable; `server/core/admin-models.ts` dan `server/functions/admin-models.ts` hanya menyediakan get settings/update availability. Tidak ada create/retire. Admin loader mengimpor static registry, credit minimum Auto menyesatkan, contextWindow dibagi 1000 menghasilkan format seperti `1.048,576k tokens`. Gunakan fakta tersebut untuk memverifikasi root cause yang masih tersisa setelah P1.

## 1. Integrasi 9Router di server

Gunakan adapter/`NINE_ROUTER_BASE_URL`, `NINE_ROUTER_API_KEY` existing dan server-only config. Verifikasi endpoint listing dan inference OpenAI-compatible terhadap versi 9Router terpasang, biasanya `GET /v1/models`, `POST /v1/chat/completions` relatif terhadap configured base (hindari `/v1/v1`). Dokumen dasar: [https://github.com/decolua/9router/blob/master/gitbook/content/en/integration/other-tools.md](https://github.com/decolua/9router/blob/master/gitbook/content/en/integration/other-tools.md) . Jangan menyusun URL upstream dari input user atau melakukan request ke host arbitrer. Zod validasi response dan ID; credentials tidak keluar ke client. Jika gateway tidak dapat diakses, catat kondisi nyata, jangan buat fake catalog/test success.

- Input exact model ID; trim whitespace luar jika perlu, pertahankan case, separator, suffix. Cek duplicate exact route/stable ID; beri pesan spesifik. Jangan menyamakan dua DeepSeek route. `auto` reserved.
- Tombol `Periksa model` mengambil discovery metadata yang benar-benar tersedia; listing absence bukan bukti absolut unsupported jika gateway versi tersebut dapat route custom ID. Lakukan direct inference probe melalui exact ID bila kebijakan gateway mengizinkan dan budget disetujui. Jangan mencoba model ID lain sebagai fallback. Verifikasi HTTP result, valid nonempty assistant text (bukan reasoning-only, error object atau empty stream), actual response/provider identity jika exposed, durasi, dan timeout. Bila actual identity tidak exposed, tandai unverified provenance; jangan menyatakan route provenance absolut. Hasil model listing bukan bukti Vision atau intelligence.
- Klasifikasikan valid/unknown/auth failure/rate limit/timeout/upstream error/invalid response secara jujur. Model pending/failed tidak diaktifkan untuk publik. Bila admin memilih menyimpan draft, tetap pending dan jelas belum tersedia. Jangan menyimpan hasil check palsu, raw secrets atau raw upstream payload berbahaya. Error copy singkat, detail teknis opsional untuk admin.
- Rate limit admin probe, batas waktu, concurrency, retry ringan hanya transient sesuai Retry-After, anggaran finite; jangan menghabiskan kredit pengguna aplikatif untuk probe. Penggunaan upstream berpotensi berbayar; script/probe harus punya batas yang nyata. UI tidak boleh melaporkan berhasil sebelum server mengonfirmasi.

## 2. CRUD dan publication gate

Buat server functions create/import, update approved editable metadata, set availability, retire/remove, re-test connection; reuse service P1. Enforce `requireAdminSession` pada setiap action, bukan sekadar route guard. Gunakan transaction/unique constraints dan race-safe duplicate handling. Tangani concurrent edit/toggle/retire dengan revalidation, tidak overwrite diam-diam. Operation result hanya DTO aman.

- Form utama hanya meminta model ID di awal. Setelah check, prefill nama tampilan/vendor bila metadata valid atau minta admin konfirmasi label dari ID (suggestion bukan fakta model). Tampilkan info route yang terverifikasi dan field metadata kosong jika tidak diketahui.
- Nama tampilan, vendor, deskripsi, search aliases dapat diedit melalui admin sesuai contract. Capability/score/tarif yang terkait benchmark **tidak boleh diset verified lewat form biasa**. Default credit untuk model pending tidak ada; sediakan status `Belum dievaluasi` dan instruksi singkat evaluasi P3/pipeline reusable, bukan 3/6/15 hasil tebakan. Credit final berasal dari evaluation policy. Metadata capability hanya verified oleh evidence yang valid. Context limit tidak ditebak.
- Model baru dapat diimport dan disimpan tanpa redeploy. Setelah connection + evaluation/policy valid, model boleh langsung muncul sebagai pilihan yang bisa dipakai (publish melalui transaksi). Connection berhasil sendiri tidak cukup untuk memberi status Verified. P2 membuat jalur kerja itu; P3 memasok empirical evaluation. Untuk model baru masa depan, admin dapat menjalankan/mengikuti runner reusable P3 dan mengimpor hasil melalui jalur backend terjaga, tidak memerlukan edit registry. Jangan menambahkan browser execution atas benchmark panjang atau menjalankan benchmark besar tanpa budget.
- Edit tidak mengubah immutable exact identity yang sudah direferensikan history. Jika route ingin diganti, import entry baru dan retire lama; jangan overwrite history. Re-activation verifikasi eligibility, disable tetap menyimpan alasan. Uji koneksi tidak mengubah rating atau availability tanpa aturan jelas. Jangan mengubah status admin nonaktif menjadi aktif hanya karena probe berhasil.
- `Hapus model` = retire. Confirm dialog menyebut nama target dan akibatnya: hilang dari selector, tidak menerima request baru, history utuh. Auto tidak dapat dihapus; backend guard meskipun request dibuat manual. Existing generation boleh selesai/stop/refund sesuai invariant P1; retirement tidak membatalkannya. Retired entry dapat diimport ulang dengan stable identity/provenance setelah pemeriksaan dan explicit action, tidak duplikasi.
- Setiap mutation update state dan audit row dalam satu transaction: `model.create`, `model.update`, `model.enable`, `model.disable`, `model.delete` (retire). Untuk test koneksi, catat event terukur bila disepakati sebagai audit administratif (`model.connection_test`), jelas hasil/failure, bukan log raw token. Simpan snapshot target ID/nama, before/after yang aman, actor, waktu, hasil; P6 memformat audit. Jangan hardcode pengecualian untuk model tertentu.

## 3. UI — minimal, terintegrasi dengan design system

Wajib component discovery sesuai bagian akhir prompt. Prioritaskan komponen existing shadcn (Button, Dialog/AlertDialog, DropdownMenu, Input, Table, Switch, Toast, Select/Combobox) atau kandidat relevan dari library yang diwajibkan. Periksa docs [https://ui.shadcn.com/docs/components/aria/data-table](https://ui.shadcn.com/docs/components/aria/data-table) ; jangan mengganti table yang sudah baik atau membangun primitive sendiri. Form add dua tahap dalam satu dialog; tombol primary biru semantic accent. Escape, focus return, busy, keyboard, touch, dialog error, duplicate, pending harus masuk flow. Success gunakan feedback singkat, bukan banner emerald berlapis. Aksi row overflow vertikal; `Edit model`, `Uji koneksi`, separator, `Hapus model` sebagai aksi destruktif. Toggle tetap quick action dengan alasan untuk disable. Jangan hilangkan kolom penting model, provider, kredit, kapasitas konteks, status; ganti `Sakelar` menjadi `Aksi`. Nama/ID panjang wrap/tooltip yang accessible. Provider teks biasa dengan kapitalisasi resmi. Tidak membuat badge baru; P4 audit global.

## 4. Refresh dan cross-surface consistency

Mutation success invalidates admin list, catalog DTO query, model selector/cache, admin metrics dan audit queries terkait. Server availability authoritative; admin tabs/client tabs yang lama dapat refresh pada focus/TTL. Jangan tampilkan model retired setelah refresh, jangan mengganti label historis. UI error mempertahankan input dan last valid data secara jujur. Bedakan no results dari failed load.

## 5. Acceptance/tests

- Admin-only create/update/toggle/retire/test; unauthenticated/non-admin denied; duplicate/invalid ID/reserved Auto/server gateway errors handled. Input URL tidak menyebabkan SSRF; no secret in client payload/bundle/logs.
- Imports exact route independently; two identical basenames not merged. Valid connection check, HTTP 200 empty/error invalid, timeout/rate-limit inconclusive, missing catalog metadata not invented. Use mocks for deterministic adapter test and clearly labeled live probe if configured/authorized; if no live gateway report blocked separately.
- Model pending cannot run new chat/compare/artifact. Eligible verified fixture appears after refresh (fixture in isolated test DB only). Inactive/retired rejected before debit or inference; toggle/retire does not delete history, stop/refund works. Restore not duplicate, audit atomic on successful mutation and rollback on failure.
- Component tests verify invoke handler/data, modal validation, busy/disabled, focus-accessible controls and correct recovery; no copy/className snapshot assertions. Existing admin models/user/catalog/routing security tests pass. Show real component discovery evidence.

Handoff P3: how to invoke import/probe/retire and submit verified evaluation results, status contract, budget config, test report. No changes to actual 14-model catalog yet.

Ini bukan instruksi untuk AI bawaan [Zona.ai](http://Zona.ai). Ini perintah kepada coding agent yang mengerjakan aplikasi [Zona.ai](http://Zona.ai).

Jika situs/komponen tidak dapat diakses, catat; jangan mengarang nama atau availability.
3. Buat discovery log singkat sebelum implementasi: kebutuhan → kandidat + URL source/docs → alasan dipilih/ditolak → kompatibilitas React/Tailwind/Radix/Base UI, lisensi, keyboard/accessibility, light/dark, dependency → komponen yang betul-betul dipakai (lokasi import dan file). Jangan menambah library besar/parallel design system apabila komponen shadcn/Radix existing cukup. 4. Adapt komponen pada Tema [Zona.ai](http://Zona.ai): Notion-inspired UI yang restrained, `paper`, `pure-white`, `ink`, `stone`, `hairline`, `accent` sesuai semantic tokens CSS. Jangan mendesain ulang halaman dari nol. Utamakan hierarki teks, whitespace, hairline separation, copy singkat natural Indonesia, ikon fungsional. Jangan menggunakan komponen yang dipilih secara mentah jika bertentangan dengan desain.
5. Ilustrasi dalam prompt adalah wireframe semantik, bukan mock data untuk dirender di aplikasi. Gunakan data aktual dan copy yang dijelaskan; jangan hardcode nama/status/angka ilustrasi. Pertahankan loading/error/empty/disabled, focus/keyboard, screen reader, touch, responsive, serta business logic yang sudah ada. Jangan menambah CTA atau elemen dekoratif yang tidak diminta. Jangan testing className, palet, snapshot markup, struktur visual, atau prose AI; test mekanisme/aksesibilitas/kontrak deterministik. Visual review hanya P9.
